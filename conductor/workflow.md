# Project Workflow

## Guiding Principles

1. **Interactive plan approval:** Plans are generated by an agent and approved (or revised) in the CLI. Plans are not written to `plan.md`.
2. **Ticket-driven work:** Tasks come from Linear or an ad-hoc prompt, and the ticket drives branch naming.
3. **Branch-based development:** Feature branches are created or checked out after plan approval.
4. **Agent-orchestrated implementation:** The CLI delegates implementation to external tools (`aider`, `gemini`, `codex`).
5. **Testing is agent-specific:** Aider runs `npm run test` by default; Conductor/Codex only run tests if the agent chooses.
6. **PR creation is optional:** Use `--no-pr` to skip; when enabled it pushes and opens PRs via `gh`.

## End-to-End Flow

1. **Start a command:**
   - `npm run conductor` or `npx tsx bin/ai-ops.ts conductor` (Gemini Conductor)
   - `npx tsx bin/ai-ops.ts aider` (Aider builder; `npm run feature` targets a legacy command)
   - `npm run codex` or `npx tsx bin/ai-ops.ts codex` (Codex)
   - `npm run agent` or `npx tsx bin/ai-ops.ts agent` (pick an agent interactively)
2. **Validate environment:**
   - `LINEAR_API_KEY` is required for ticket selection.
   - `gh` is required unless `--no-pr` is set.
   - `aider` is only required for the Aider flow.
   - Missing AI API keys generate warnings but do not block startup.
3. **Select the target repo:**
   - Choose `Backend`, `Frontend`, or `Other`.
   - Paths come from `BACKEND_REPO_PATH` and `FRONTEND_REPO_PATH`, or a manual path.
4. **Select the task:**
   - Linear tickets are the default.
   - Ad-hoc tasks use the format `Title:Description` and create an `ADHOC-<timestamp>` ticket.
5. **Planning loop:**
   - The agent generates a plan.
   - The user can approve, request changes, or cancel.
6. **Branch creation:**
   - Uses `ticket.branchName` when provided, otherwise `feature/<identifier>-<slug>`.
   - The branch is created or checked out after plan approval.
7. **Implementation:**
   - The agent executes the approved plan in the selected repo.
   - Conductor uses `gemini`, Codex uses `codex`, and Aider uses `aider`.
8. **Tests (Aider only):**
   - Runs `npm run test` in the target repo unless `--skip-tests` is set.
   - If tests fail, Aider can attempt fixes with user confirmation after repeated failures.
9. **Post-implementation:**
   - The CLI can commit changes with a default message `feat(<ID>): <title>`.
   - If enabled, it pushes the branch and opens a PR via `gh pr create`.

## Conductor Flags

- `--model <name>`: Override the Gemini model.
- `--extensions <comma-list>`: Override extensions (default: `conductor`).
- `--approval-mode <mode>`: Pass through approval mode to the Gemini CLI.
- `--allowed-tools <comma-list>`: Restrict Gemini tool usage.
- `--debug`: Enable Gemini debug output.
- `--no-pr`: Skip push/PR creation.
- `--task <value>`: Accepted but ignored; tasks always come from ticket selection.

## Aider Flags

- `--model <name>`: Override the Aider model.
- `--editor-model <name>`: Override the editor model.
- `--skip-tests`: Skip the Aider test loop.
- `--dry-run`: Generate a plan and exit before implementation.
- `--no-pr`: Skip push/PR creation.

## Codex Flags

- `--model <name>`: Override the Codex model.
- `--profile <name>`: Use a Codex profile.
- `--no-pr`: Skip push/PR creation.
